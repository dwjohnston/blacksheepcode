There seems to be quite a popular view currently that says: 

> Reading the code that AI outputs is like reading the compiled assembly. That's what people did once upon a time when compilers were first invented.

or

> We're no longer software engineers, we're CTOs. The CTO doesn't understand every line of code in the organisation they manage either. 

On the first point, I think that first point does poigantly get at a feeling of discomfort we are currently experiencing as software developers - there is an amount of having to let go.  

 is that we don't trust don't the technololgy when we first use it, and as we use it more and see it being reliable then we can trust it more. 

But this isn't to say that it's silly to to this period of verification - it could be considered sensible due diligence. 

There's a larger point here. Yes - when I use a compiler I just trust that it works. But that's not to say that no one knows how a compiler works. _Somebody knows how the compiler works_. 

When I write some high level application code, there are multiple layers of abstraction it's built on top, that I do not have a solid understanding of, and nor do I need one. I don't need to know exactly how a car works, to drive one, either. 

But in the pre-AI world, all of those layers are built by one one who understands what it's doing, however flawed their understanding may be. 

And yes - in the pre-AI world, there's was always a bit of not-really-understanding-the-thing-but-good-enough-to-get-the-thing-going. 

But in the AI world if we're building whole layers of our application on code that no human go to understand - that that chain of understanding is broken.

## There's plenty of code that it's ok not to understand 

There absolutely is a place for not understanding the code.

### Code that from the outset we are aren't trying to understand

I've been experimenting with ralph loops and autonomous agentic workflows to produce a zero player game. Perhaps a post for another time. 

In these, from the outset the goal was never to pretend to understand it, this is fine. 

### Well encapsulated code

This is like copy pasting an email regex of stack overflow - it works, you have some tests for it, you don't need to understand it. Its blast radius is limited.
